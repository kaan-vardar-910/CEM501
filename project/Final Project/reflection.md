Reflection

This project was one of the most interesting and challenging experiences I have had during my studies. The goal was to develop an AI-powered communication assistant for a Construction Engineering and Management project manager. At the beginning, the idea seemed straightforward: create a system that could help manage emails and generate documents. However, as the project developed, I realized that building a useful assistant required much more than simply connecting an AI model to a user interface.

One of the first lessons I learned was the importance of understanding real business processes before writing code. In construction projects, communication is a critical part of daily operations. Project managers spend a significant amount of time reading emails, preparing reports, responding to requests, and creating formal documents such as RFIs and delay notices. Instead of focusing only on AI capabilities, I tried to understand these workflows and design a system that could support them in a practical way.

The project allowed me to work with several technologies and combine them into a single application. I used Python as the main programming language and integrated email services, document generation tools, weather data, Telegram notifications, and the Claude language model. Bringing all these components together taught me how different systems communicate and how important it is to design clean interfaces between modules. I also learned that software architecture is just as important as individual features. A well-organized structure makes future improvements much easier.

Another important lesson was the value of reliability and safety. Since the system can draft and send emails, I understood that mistakes could have real consequences. For this reason, I implemented several guardrails, including recipient validation, content checks, rate limits, and mandatory human approval before sending any message. This experience showed me that building AI systems is not only about automation but also about controlling risks and maintaining trust.

The daily report module was probably the most challenging part of the project. It required processing information from multiple file formats, extracting useful data, and generating structured reports. I learned that AI performs much better when tasks are divided into smaller steps. Instead of asking the model to generate a complete report directly, I first extracted structured information and then used that information to create the final report. This approach produced more consistent and reliable results.

I also gained a better understanding of the strengths and limitations of large language models. Claude was very useful for generating summaries, drafting professional responses, and creating construction-related documents. At the same time, I learned that AI should not be trusted blindly. Human review remains necessary, especially when dealing with contracts, project communications, and formal notices. This reinforced my belief that AI works best as an assistant rather than a replacement for professional judgment.

Looking back, there are several improvements I would like to make in the future. The current system uses JSON files for storage, which is sufficient for a demonstration project but not ideal for larger-scale use. I would also like to implement user authentication, a smarter hybrid email triage system, and a learning mechanism that adapts to user corrections over time. These additions would make the platform more scalable and more intelligent.

Overall, this project helped me connect concepts from construction management, software development, and artificial intelligence in a practical way. More importantly, it taught me how technology can be designed to solve real industry problems and my problems. The experience strengthened both my technical skills and my understanding of project workflows, making it one of the most valuable projects I have completed during my academic journey.
